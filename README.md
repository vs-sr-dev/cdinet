# cdiNet

A web browser for the Philips CD-i, through the player's serial port.

In 1995-96 Philips sold **CD-Online** (Web-i in the US): a 14.4k modem on the CD-i's serial
port and a disc that browsed the web, read mail and news. The disc is lost; the idea is
not. cdiNet does it as a thin client: a proxy on a PC does everything the modern web needs
(TLS, HTML, search, pictures) and sends the CD-i screens it can draw: text wrapped to its
columns, links, and pictures in a few colours.

```
CD-i (cdi/)  <-- serial line, 19200 baud -->  proxy (proxy/)  <-- HTTPS -->  the web
 text, links, pointer, keyboard, pictures      fetch, simplify, wrap, quantize
```

Status: works in the [cdiPC](https://github.com/vs-sr-dev/cdipc) emulator (its
`--serial` option carries `/t2` over TCP). A real player needs a serial cable or a Hayes
WiFi modem, not tried yet.

## Using it

1. The proxy (Python 3; [Pillow](https://pypi.org/project/pillow/) for pictures):

   ```
   python proxy/cdinet_proxy.py            # waits on 127.0.0.1:6400
   ```

   `--search wikipedia|wiby|frogfind`, `--colours 2-48`, `--host 0.0.0.0` to be reached
   from another machine.

2. The CD-i, in cdiPC:

   ```
   cdipc --serial 127.0.0.1:6400 cdi/disk/CDINET.CUE
   ```

   PLAY CD-I. Point at a link and press button 1; button 2 goes back. **Go** opens a
   keyboard for an address or words to search; **Prev** / **Next** turn the screens of a
   long page; `[image]` links show the picture, drawn as it arrives.

## Building the disc

The CD-i program is C for Microware's Ultra C, built and mastered with the Microware CD-i
SDK in Docker (the `cdi-toolchain` image: wine for the compiler, DOSBox for `vcdmastr`).
The SDK is not part of this repository.

```
cd cdi
docker run --rm -v "<sdk>:/opt/cdi-sdk:ro" -v "$(pwd):/work" cdi-toolchain:latest make clean all
```

`tools/run_headless.sh OUT SECONDS [cdipc options]` builds the disc, starts the proxy for
one call and runs cdiPC headless against it, with a screenshot every 5 seconds.
`tests/fake_cdi.py` speaks the protocol from a PC, to try the proxy alone.

## Inside

- `docs/protocol.md`: the line protocol. One request, one reply of at most 106 bytes,
  because the BIOS's serial driver keeps 128; frames with CRC and sequence numbers.
- `cdi/src`: `main.c` (the browser), `link.c` (the serial line: `/t2` in raw mode, every
  SCF terminal feature off), `video.c` (plane A in CLUT7, the hardware cursor), `draw.c`
  (6 x 10 text), `kbd.c` (the on-screen keyboard), `picture.c` (LZSS decoding into the
  screen as the bytes come), `font.c` (generated by `tools/mkfont.py`).
- `serecho/`: the first test, a raw echo on `/t2`.
